# Подготовка компьютера Alkaloid

Профиль: `profiles/alkaloid.yaml`. Домен AD: `alkaloidad.local`, короткое имя: `AlkaloidAD`. Имя компьютера: `PCRUS` и выданный номер (например, `PCRUS123`; звёздочки из шаблона вводить не нужно).

## Что выполняет профиль

- Переименование в имя, указанное при запуске.
- Присоединение к `alkaloidad.local` с интерактивным запросом доменных учётных данных.
- Включение RDP.
- Отключение сна и гибернации **при питании от сети**.
- Постоянный маршрут `10.0.0.0/8` через `10.50.6.20` до присоединения к домену. Интерфейс определяется по маршруту до шлюза.
- Установка Chrome, 7-Zip, Office 2019, SCCM Client, TeamViewer Host и SEP нужного варианта из локальных пакетов.

`office` и `roaming` обозначают сценарий выдачи, а не фактический департамент сотрудника. Они выбирают разные пакеты SEP. `domain.ouPath` оставлен пустым: компьютер будет добавлен в стандартное расположение домена. Выбор Roaming не перемещает компьютер в Roaming OU. Когда администраторы сообщат точные distinguished name для OU, внесите их в соответствующие варианты профиля.

### Локальные пакеты

Сохраняйте полные каталоги с сопутствующими файлами:

```text
installers/
  GoogleChromeStandaloneEnterprise64.msi
  7z2604-x64.msi
  TeamViewer_Host_Setup_x64.exe
  TelegramSetup.exe
  HappSetup.exe
  CorpDesk-1.4.9.msi
  MSOffice2019/ (setup.exe, office2019.xml, Office/Data/...)
  SCCM-Client/ (ccmsetup.exe, x64/ и остальные файлы)
  SEP-Antivirus/RU8-office/ (setup.exe и sylink.xml)
  SEP-Antivirus/RU8-roaming/ (setup.exe и sylink.xml)
```

Office запускается через `scripts/Install-AlkaloidOffice.bat`: это переносимый аналог исходного `install.bat`, в котором был жёсткий путь `C:\MSOffice2019`. Используется существующий `office2019.xml`; с его `Display Level="Full"` интерфейс Office будет виден. Папка `Office/Data` должна оставаться рядом с setup.exe.

Telegram и Happ включены в оба сценария и доступны отдельными галочками.
Скачайте Windows x64 EXE-установщики с [сайта Telegram](https://desktop.telegram.org/)
и [сайта Happ](https://www.happ.su/main/ru) и переименуйте их в
`installers/TelegramSetup.exe` и `installers/HappSetup.exe`. Нужны установщики,
а не portable-сборки.

Telegram запускается в тихом режиме Inno Setup, без перезагрузки и запуска приложения,
с каталогом `C:\Program Files\Telegram Desktop`, чтобы бинарные файлы были доступны
будущему пользователю. Проверяется наличие `Telegram.exe` в этом каталоге.
Штатные ярлыки установщика могут относиться к текущему администратору.

Happ запускается с обычным мастером: подтверждённые параметры тихой установки для
его EXE пока отсутствуют. Завершите мастер, затем AutoInstaller продолжит задачи.
Повторная установка пропускается при наличии записи `Happ*` в списке удаления
программ HKLM/HKCU. Подписки и настройки подключений вручную задаются после установки.

SCCM запускается через `ccmsetup.exe /noservice` с ожиданием процесса и появления `CcmExec`. Назначение сайта и связь с management point нужно проверить отдельно по корпоративной конфигурации. `scepinstall.exe` из каталога SCCM не запускается.

SEP запускается без выдуманных silent-параметров: режим установки определяется экспортированным пакетом, может понадобиться участие оператора. Не соглашайтесь на перезагрузку, пока выполняются задачи. Наличие службы `SepMasterService` означает пропуск повторной установки; переключение Office/Roaming у уже установленного SEP не меняет его группу и sylink-конфигурацию.

CorpDesk есть в каталоге пакетов, но исключён из обоих списков установки для текущего теста. Для новых ноутбуков добавьте `"corpdesk"` в `departments[].software` нужного варианта. Уже установленная служба `CorpDesk` предотвращает повторную установку.

## Подготовка и запуск

1. Установить Windows 11 Pro и подготовить локальную учётную запись администратора `Administrator`. Пароль получить отдельно.
2. Подключиться к корпоративной сети. Проверить корректный DNS и доступность шлюза `10.50.6.20`. Маршрут добавляется автоматически первой задачей, повторный запуск не создаёт дубликат на том же интерфейсе.
3. Подготовить локальный пакет `installers/GoogleChromeStandaloneEnterprise64.msi` либо изменить `installer.path` в профиле на фактический путь к MSI из `AlkSetup/soft`. Относительные пути отсчитываются от файла профиля. Пакет в репозиторий не входит.
4. Из корня проекта проверить план, подставив выделенное имя компьютера:

   ```powershell
   .\Start-AutoInstaller.ps1 -ProfilePath .\profiles\alkaloid.yaml -DepartmentId office -ComputerName PCRUS123 -NoUi -DryRun
   ```

5. Запустить настройку из PowerShell с правами администратора:

   ```powershell
   .\Start-AutoInstaller.ps1 -ProfilePath .\profiles\alkaloid.yaml -DepartmentId office -ComputerName PCRUS123 -NoUi
   ```

   Для выездного сотрудника заменить `office` на `roaming`. Для графического интерфейса:

   ```powershell
   .\Start-AutoInstaller.ps1 -ProfilePath .\profiles\alkaloid.yaml
   ```

   В интерфейсе выбрать сценарий, ввести имя компьютера и оставить галочки только у нужных действий. Кнопки `Select all` и `Deselect all` отмечают или снимают все галочки. При смене сценария все действия отмечаются заново.

   Профиль выставляет английский (US) первым языком и вводом по умолчанию для текущей учётной записи, сохраняя остальные языки. Настройку будущего доменного пользователя нужно проверить отдельно.

6. Проверить результаты задач и выполнить перезагрузку после переименования и присоединения к домену.

## До первого входа сотрудника: ручные действия

- Отключить сон от батареи, если это требуется политикой компании: профиль меняет только питание от сети.
- Отключить быстрый запуск Windows через параметры электропитания → действия кнопок питания → изменение недоступных сейчас параметров → снять «Включить быстрый запуск».
- Положить VPN и письмо в `IT/copy/IT`, а готовые ярлыки с целями в `C:\IT` — в `IT/copy/shortcuts`. Задача копирования переносит их в `C:\IT` и `%PUBLIC%\Desktop`.
- Проверить результаты установки пакетов профиля. Дополнительный софт, не включённый в профиль, установить по принятому в компании порядку.
- После присоединения и перезагрузки добавить `AlkaloidAD\ithelpdeskrus` в локальную группу администраторов. В PowerShell от администратора (SID не зависит от языка Windows):

  ```powershell
  $administrators = Get-LocalGroup -SID 'S-1-5-32-544'
  $account = 'AlkaloidAD\ithelpdeskrus'
  if (-not (Get-LocalGroupMember -Group $administrators | Where-Object { $_.Name -ieq $account })) {
      Add-LocalGroupMember -Group $administrators -Member $account
  }
  ```

- При необходимости ручной установки SEP исходные сетевые каталоги:
  - Office: `\\srvrusfs\Helpdesk_Install\Install_New_PC\03. SEP antivirus\RU8-office`.
  - Roaming: `\\srvrusfs\Helpdesk_Install\Install_New_PC\03. SEP antivirus\RU8-roaming`.

  Профиль использует локальные копии `installers/SEP-Antivirus/RU8-office/setup.exe` и `installers/SEP-Antivirus/RU8-roaming/setup.exe`.

## После входа сотрудника

- Установить/настроить Teams и Webex в учётной записи пользователя.
- Настроить Outlook как почтовое приложение по умолчанию.
- Настроить Google как поисковик; при необходимости выбрать Chrome браузером по умолчанию.
- Войти в TeamViewer: `ithelpdeskrus@alkaloid.com.mk`. Пароль получить отдельно.

## Активация Windows и Office, выбор OU

Кому: `sysadmins@alkaloid.com.mk`
Копия: `ithelpdeskrus@alkaloid.ru`

Подставить имя компьютера, выбрать `Roaming OU` или `Office OU` и указать данные TeamViewer по принятому защищённому каналу. Шаблон без паролей:

```text
Hello,

Please activate PCRUS<номер>
Windows+Office+Roaming OU

TeamViewer <ID>
Password <передан отдельно>
```

Для Office заменить `Roaming OU` на `Office OU`. Отслеживать ответ и при необходимости напомнить администраторам. По внутренней инструкции допускается выдача до завершения активации; тогда согласовать с сотрудником включение ноутбука для завершения работ.

## Дополнительные действия

- Создать `\\srvrusfs\AO\<департамент>\<фамилия>` для авансовых отчётов и выдать права сотруднику и руководителю. Фактический департамент, учётные записи и уровень доступа уточнить перед настройкой.
- Настроить Outlook на смартфоне и почту на iPad:
  - сервер: `webmail.alkaloid.com.mk`;
  - домен: `AlkaloidAD`;
  - имя пользователя: часть почтового адреса до `@`;
  - пароль: пароль AD сотрудника, вводится при настройке.
- Подготовить визитку с логином; передать пароль по принятому в компании порядку.

## Inventory и BitLocker

BitLocker включён в профиле Alkaloid и доступен отдельной галочкой.
После переименования/ввода в домен задача отправляет серийный номер, Recovery Password
и фактически настроенное имя компьютера (`device_name`) в
`https://invent.datacloud.msk.ru/api/bitlocker-keys`.
При несовпадении введённого имени с настроенным Windows задача останавливается.
Имя после успешного переименования читается из конфигурации Windows до перезагрузки.

Ключ API хранится на переносимом носителе отдельно от профиля:
`runtime/inventory-api-key.txt`. Относительный путь задаётся в профиле вместе
с `apiKeyFileFormat: text`. Он работает на другом компьютере без привязки
к DPAPI текущего пользователя. Скрипт `scripts/Set-InventoryApiKey.ps1`
запрашивает ключ скрыто и сохраняет этот runtime-файл на флешке.
Каталог `runtime` исключён из Git. Ключ также можно передать переменной процесса
`AUTOINSTALLER_INVENTORY_API_KEY`, которая имеет приоритет над файлом.

Ключ восстановления сохраняется в отдельный файл на рабочем столе администратора
и отправляется в API до запуска шифрования. Если отправка не подтверждена, новое
шифрование не запускается. Для нового шифрования требуется готовый TPM;
при повторном запуске существующий recovery protector переиспользуется,
приостановленная защита возобновляется после повторной отправки ключа.
Ключи не включаются в обычные логи, отчёты или resume state.
